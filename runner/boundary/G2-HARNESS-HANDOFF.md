# Actual-route G2 and protected candidate execution

No model calls are implemented by the operator CLI. Run `node runner/boundary/g2-harness-cli.ts prepare` to create private synthetic fixtures and a separate guardian namespace on the dedicated daemon. Keep the returned fixture and prompt paths private. Stage the public positive control with `stageG2PositiveTask` in an independent task clone before normal trusted task staging. Never stage the fixture, guardian volume, hidden oracle/reference, or host ambient configuration into the worker.

The parent supplies `runG2Harness` with accepted final-container G1 evidence, a **distinct actual-route-G2 admission**, its authoritative consumed-ledger verifier, native execution callback and awaited namespace teardown/reap callback. Admission must bind preregistered source, assignment, invocation and final boundary identity; a callback echo is insufficient. The deadline covers execution and admission verification. Failed/stuck callbacks fail closed and retain private recovery. No held-out admission is implied.

Native receipt normalization requires exactly matched start/result events by invocation, kind, exact requested path/command and correlation ID. Add typed `outcome` from actual tool status/control proof; model prose and guessed stderr cannot establish denial. Missing native read/search/http/config capability or trace remains unavailable and blocks qualification. Shell substitutes do not fill these channels. Trace/output buffers remain private and bounded. Parent must attest the actual Responses SSE route and complete native provider/tool/extension inventory using independent instrumentation.

Use `normalizeG2NativeReceipt`, then `runG2Harness`, to evaluate all public fixture probes. Evaluation requires task positive controls, denial on every requested channel, private guardian isolation, absent/reaped worker, baseline-integrity export and preserved partial task file after timeout/cancellation. Raw/base64/hex synthetic bytes and values split across chunks are scanned; report fields expose only probe IDs and booleans. Unknown/incomplete evidence fails closed. Offline `scan PRIVATE_FIXTURE PRIVATE_RESULT NEW_REPORT` forcibly marks JSON evidence synthetic and can never grant G2. `cleanup PRIVATE_FIXTURE` verifies private directory ownership, exact guardian identity and labels before removal.

The final worker/broker/config identities remain exactly those in `evidence/fallback/final-profile-public-inputs.json`; no external wildcard, refresh permission, image substitution or native built-in parity is added.

## Post-export oracle caller contract

`executeProtectedJudgeChild({candidateRoot,module,exportName,requests,timeoutMs})` accepts only a safe bounded candidate snapshot and behavioral argument arrays. It runs the candidate in a nonprivileged, read-only, network-none container with no auth, host mounts, socket or hidden reference; private PID/IPC/cgroup namespaces; 256 MiB, 0.5 CPU, 32 PIDs and bounded temporary storage. The trusted staging utility receives only the candidate snapshot. Explicit teardown removes the namespace before returning and confirms absence, then removes its exclusively labelled volume.

Returned `stdout` is PRIVATE and untrusted, even when exit status is zero. The protected parent oracle computes expected results itself, parses/bounds candidate output and produces boolean judgment/protected logs. Never put candidate stdout in model context. Candidate module calls must not run via unrestricted host node/execFileSync, including post-export validation. S0 must adapt actual oracle callers before `oracleCallerAdapted` and `postExportCandidateExecutionProtected` may be set from authoritative integration evidence. Worker-only success is reported separately and cannot grant whole-workflow G2.
