## W6.2 — per-case USD budgets, explicit budget-stop records, coverage columns

Source: V11PLAN §6.2 (J5 M3 budget survivorship / M4 denominators); the accepted D9 envelope (RS-9 `rs9-eval-statistics.md` @ `dfe66be` §0.3, owner-accepted per the v11 board's D9 row).

### Per-case USD budgets (D9 defaults, fail closed)

- **The mapping is an exact-cell table** (`D9_PER_CASE_USD`, `runner/budget.ts`), keyed by (driver lane, served model id) — the cell identity the row schema and ADR-0001 axes dispatch on: `$0.05` on the ai-sdk flash cells (`glm-5.3-flash`, `deepseek-flash`), `$0.10` on the claude-agent / subprocess / acp GLM lanes, `$1.00` on the frontier Claude cell (`claude-agent @ claude-opus-5-5`; the entry documents the envelope — the CLI's ADR-0001 axis guard still refuses that model on a non-ai-sdk lane today). An exact table, not a `*-flash` pattern, on purpose: a pattern would silently grant caps to future model ids; an unmapped cell must fail closed until the envelope is extended deliberately. The accepted caps are cell-scoped; the role never changes the amount.
- **Fail closed at the CLI, before any spend**: with no `--max-usd-per-case` and no mapping for the cell, the run is a usage error (exit 2) naming the cell, the accepted table, and the escape hatch. Resolution sits after the ADR-0001 axis guard in `parseArgs`, so a mis-axed run's refusal message is unchanged.
- **Two-grain binding** (`runner/index.ts`): the resolved per-case budget rides each invocation's `budget.maxUsd` (driver-enforced on the lanes that honor `Budget.maxUsd` — claude-agent, subprocess) AND the run governor's cumulative cap, `perSuiteUsdCap(perCase, caseCount)` — the USD mirror of WB-1.6, rounded to 6 decimals so `0.05 × 40` is exactly 2. The governor grain is what enforces the cap on the lanes whose driver ignores `maxUsd` (ai-sdk, acp). A case that overspends its share trips the cumulative cap and gates only the tail — visibly, as budget-stop absences.
- **Fake runs resolve like real ones** (decision): the smoke cells then prove the D9 table covers every cell the matrix can dispatch. FakeDriver ignores invocation budgets and its modeled cost is orders of magnitude below the caps, so smoke behavior is unchanged.
- **Legacy `--max-usd` semantics preserved verbatim** (decision): it stays a run-level cap (and the invocation grain's cap, as today) and is mutually exclusive with `--max-usd-per-case` — one dimension, two grains, same rule as the WB-1.6 token pair. A `--max-usd`-alone run records no per-case manifest fields.
- **No suite.json budget field** (decision): one invocation is one cell, so the D9 table plus the explicit flag are the only sources of truth; a suite-grain override would fork them.

### Budget stops are explicit records, never silent no-rows

- **Undispatched (run budget gate refused admission):** the case joins `RunSuiteResult.absences[]` with a `budget-stop: …` cause — surfaced by the CLI's stderr block and, in `run.json`, in the entry's `absences[]` beside the dispatch-only absences. The journal convention is unchanged (missing job ids ARE the not-dispatched list; the stop stays on the run-finished event and `gatedByBudget`), but the case is no longer visible only as a stderr line: it is a structured, machine-filterable record. Coverage makes the same gap mechanical (below).
- **Dispatched but stopped on its budget (`stopReason: 'budget'`):** the row stays — the case ran, and its partial spend and configured-but-failed probes are evidence (the existing "governed stops are NOT absences" doctrine, `runner/README.md`) — but it now carries `stopCause: 'budget'`, the plan's cause column. The cell counts it in `budgetStops` and excludes it from `coveredCases`.

### expectedCases / coverage — parity as a computed property

- **Every row carries `expectedCases`** (the suite's declared case count). The denominator must ride the rows because the gated cases have no rows by design (I9) — a consumer holding only `rows.jsonl` can then compute any cell's coverage without the manifest.
- **Cells carry `expectedCases`, `coveredCases`, `coverage`** (emitted together, whenever the rows declare it) plus `budgetStops` when non-zero. `coveredCases` counts DISTINCT case ids whose row is complete evidence. `aggregate()` stays pure rows→tables — no signature change; a conflicting `expectedCases` across a cell's rows throws (malformed input, never an arbitrary denominator).
- **`isAtCoverageParity(a, b)`** (exported): true iff both cells sit at coverage 1 — the mechanical gate RS-9 §1.3 requires before a comparison may be labelled anything stronger than *descriptive*. A cell without the coverage columns (pre-W6.2) reports NOT at parity: unknown coverage is never assumed equal. Case-set identity (equal counts, different cases) is checkable by pairing rows.jsonl case ids; the counts stay losslessly recoverable from the rows.
- **Manifest (`run.json`) records `expectedCases`** — even for a fully gated suite, which publishes no rows to carry it — **and `maxUsdPerCase` + `maxUsdPerCaseBasis`** (`'d9-default'` | `'explicit'`) so a snapshot states the cap that bound it.

### Compatibility

- All row/table changes are additive-optional: pre-W6.2 rows re-aggregate to their original cell shapes, so every committed snapshot validates and a regrade reproduces its tables byte-identically. The strict PR #31 replay validation (`scripts/regrade-snapshots.mjs --check reports/snapshots/2026-09-21-wb1`) passes with 0 files changed. All historical `workspace-unbound` markers and the P5/F4/F6 semantics are untouched.
- **Bounded retry on timeouts and rate limits** (the fourth clause of plan §6.2) is **deferred, not forgotten** (decision): the brief's W6.2 scope and acceptance name the budgets, the cause records, and the coverage columns only; a dispatch-grain retry needs the driver-seam `errorClass` vocabulary (W3.3/W2.6, toolkit-side, outside this lane's file area) to distinguish a retryable timeout from a model outcome. Forcing it now would retry unclassifiable failures and change attempt semantics the journal already records. Recorded here as the remaining W6.2 residue for whoever owns the retry slice.

## W6.3 — leakage excision and the eval-root CI check

Source: RS-9 (`research/rs9-eval-statistics` @ `dfe66be`), `rs9-eval-statistics.md` §4.3 and `evidence/rs9/leakage-inventory.md`.

### Excision (RS-9 §4.3 A–C)

- **Allowlist-built eval root** (`scripts/eval-root.mjs build`). Holds only `runner/**/*.ts`, the three runtime schemas, the denylist policy, `package.json`, `toolkit.lock`, the judge, each suite's fixture entries (`check.mjs`, `package.json`, `src/**`, `test/**`, or a thread payload), stripped `suite.json` files (`id`, `fixture`, `task.prompt`, `probe.kind`, `probe.check`), `node_modules/`, the `EVAL-ROOT.json` marker, and one planted sentinel. The following never enter the root: FAULT.json records, `.label.json` sidecars, `catalog/`, every `.md` file (PROVENANCE, REPRODUCTION, LABEL-GUIDE, READMEs, DECISIONS), `docs/`, `reports/`, `test/`, `.git`, `scripts/` and `.github/`. A fixture holding anything else fails the build instead of being dropped silently.
- **`task.notes` and `probe.expected`** are stripped from the root. The classifier's expected verdicts and label-sidecar flags move to a runner-only answer key outside the root (mode 0600). `loadSuite(dir, key)` fills in the verdicts before schema validation. A stripped classifier suite without its key does not validate.
- **`--out` outside the root.** Out dirs stay under `reports/` in the checkout, which is not in the root. In the matrix job the checkout is then pruned to the planted sentinel alone (`test/`, `.git` and everything else), so `reports/` snapshots are gone before any model-facing step.
- **Other host copies.** In CI there are none (the pruned checkout is the only copy). Locally they remain reachable by host-reach lanes; see the residual risks.
- **Prompts.** The 16 fix-stating prompts (micro-1..5, breadth-01..10, canary-03) are rewritten to symptom-only tails. Micro gets new symptom text because it has no FAULT.json. The mechanism-naming `failure_symptoms` of breadth-03, 09 and 10 are rewritten. canary-03 is changed at its generator recipe and regenerated.
- **Classifier prompt.** The marker is now `Thread payload:`; the fixture path is gone.
- **Hint comments.** Removed: canary-04 `merge.ts:1-4` (edited in the merge substrate and regenerated), breadth-03 `discount.ts:1`, and breadth-02 `paging.ts:7`. Each record's `validation.fix` is edited to match, so both-states and adequacy still hold.
- **B.10.** Materialized workspaces exclude `node_modules/` from the persisted patch.

### CI check (RS-9 §4.3 D)

- **Static scan** (`scripts/eval-root.mjs scan`) runs in `ci.yml`'s required static job and before dispatch in the `suite.yml` smoke and matrix jobs. It re-derives the allowlist from the checkout and fails on:
  - any extra, missing or altered file;
  - an RS-9 forbidden path class;
  - a symlink leaving the root, or a symlinked `node_modules`;
  - an answer marker in a data file or a prompt (`FAULT`, `canonical fix`, `.label.json`, `"expected"`, `catalog/`, `validation.fix`, fault-record and sidecar fields, `"notes"`, and fixture paths in prompts);
  - a prompt sharing a 6-token span with its fix diff;
  - a stripped suite carrying anything beyond the dispatch fields;
  - a key that lies inside the root, was built for another root, or does not cover exactly the root's classifier cases;
  - a missing or wrong sentinel.
- **Dynamic sentinel.** `cq-sentinel-<32 hex>` is planted as a file named after the token beside the fixtures, in the key, and (in the matrix job) in the pruned checkout. The runner refuses to run from a root without `--answer-key`. For every case it scans the structured output, error, tool denials, any driver throw, the patch, the store-side session transcript and CLI sidecar, and every workspace file and symlink target. The needles are the token, the key path, the planted paths, and `<root>/`. A hit publishes no row and no prediction, records a `sentinel-contamination` absence in `run.json`, and exits 2.
- **Smoke from the root.** The smoke job runs every smoke suite from the built root with its key, which proves the allowlist is complete and that the sentinel stays silent over every real fixture.

## W6.4 — the acp leg is non-fatal (D7) and the real matrix carries the USD ceiling

Source: V11PLAN §3 D7 (acp lane: "not provisioned" and non-fatal; keep it in the toolkit), D9/D10 (the USD-ceiling unpause precondition), §6.4.

### ACP leg non-fatal, every failure recorded (D7)

- **Mechanism: a job-level `continue-on-error` expression on the `matrix` job**, scoped to the acp leg alone: `continue-on-error: ${{ matrix.cell.driver == 'acp' }}`. Decisions:
  - *Job-level, expression-scoped — not step-level, not blanket.* The five cells share one job definition, and the expression is evaluated per matrix leg, so exactly the acp leg becomes survivable; a bare `continue-on-error: true` (forbidden by the workflow-contract test) would make every leg survivable. Step-level `continue-on-error` on the acp-specific steps was rejected because it cannot cover steps that have no acp-specific handler (a checkout or `npm ci` flake landing on the acp leg alone would still crash the run) and cannot express "record whatever died".
  - *Failure stays LOUD on the leg.* The leg still exits non-zero and shows red — no step's exit status was softened to a skip. The preflight's exit-status discipline is unchanged (rc 3 = probed no-credentials and rc 124 = timeout remain the only skip classes; everything else still `::error::` + `exit 1`); the install step still fails; a hard-failed eval cell still exits 1. What changes is only the blast radius: the workflow run stays green and `needs.matrix.result` reads `'success'`, so the snapshot still publishes the surviving cells' evidence.
- **Explicit recording on every failure path.** A new `reports/eval/ACP-FAILED` marker (content: the cause in one line) is written by:
  - the install step (harness install failure), before its `exit 1`;
  - both preflight hard-fail branches (infrastructure rc≠0/3/124, and auth-OK-without-probe-record), before their `exit 1`;
  - the eval step, when the acp cell hard-fails (runner rc≥2 — usage, validation, sentinel contamination — or zero discovery), before `exit "${hard_fail}"`;
  - a new **always-on recorder step** ("Record the acp lane status (W6.4, D7)", `if: always() && matrix.cell.driver == 'acp'`), which runs last on the acp leg, keys on `job.status`, and guarantees the marker exists for ANY failure — including paths with no acp-specific handler. It writes only when no cause-specific marker is already present, and it records nothing on a clean or skipped pass (a skip has its own honest marker, ACP-SKIPPED).
  - The marker rides the `if: always()` eval artifact (it never publishes to snapshots — the copy loop takes only tables/rows/manifests/journals/patches/outputs). The leg's `::error::` annotations, step summary and log carry the specific diagnosis.
- **Snapshot learns the new degraded shape.** With continue-on-error, a FAILED acp leg leaves `needs.matrix.result` at `'success'`, so the snapshot's clear-on-success branch needed the new proof: the dated dir is cleared only when there is no ACP-SKIPPED, **no ACP-FAILED**, and no DISPATCH-ONLY marker — a failed or skipped acp lane merges, never clears (an earlier same-day authenticated acp run's tables stay).
- **D7 "provision it" is still the open half.** The lane stays in the matrix and stays non-provisioned on this repo's CI (agent-side zcode credentials cannot be provisioned from repo secrets). This change only makes the not-provisioned posture safe: any provisioning/auth/runner failure is now an explicitly recorded absence rather than a crashed matrix.

### USD ceiling on the real matrix (D9/D10)

- **Every real matrix invocation carries an explicit per-case ceiling.** Each matrix cell declares `usd_per_case` — the accepted D9 envelope's cap for its exact (driver, served model) cell (0.05 on both ai-sdk flash cells, 0.10 on the three driver-axis GLM lanes) — and the eval step passes it as `--max-usd-per-case "${MATRIX_USD_PER_CASE}"` on every suite invocation. The runner (W6.2, unchanged) binds it at the invocation grain and as the cumulative run cap, so an overspend is a loud budget-stop absence with a recorded cause, never silent truncation. This reverses the DD-9-era "no USD cap rides the cells" posture, which existed because the served GLM id was then unpriced; the owner accepted the D9 envelope since, and W6.2 built its enforcement.
- **Workflow/runner drift is mechanically excluded.** `test/workflow-contract.test.ts` parses the cell blocks and asserts each cell's `usd_per_case` literal equals `d9PerCaseUsd(driver, model)` from `runner/budget.ts` — a new cell without a cap, or a cap that drifts from the envelope, fails the unit gate. A cell that somehow reaches the runner without a cap fails closed there too: `--max-usd-per-case ''` is a positive-number usage error (exit 2).
- **Unattended real runs without ceilings are refused (runner-side gate).** A real-lane (non-fake) run under `GITHUB_ACTIONS=true` whose only cap is the legacy run-level `--max-usd` is a usage error (exit 2, before any dispatch) naming the cell and the D9 cap. CI is the unattended signal (the env var every Actions runner sets — no new flag); attended local runs keep the legacy `--max-usd` semantics verbatim (the recorded W6.2 decision), and fake runs are exempt (the smoke spends nothing; its D9 resolution already proves the envelope covers every dispatchable cell). The smoke's no-USD-flag fake shape in CI is regression-tested to keep passing with its `d9-default` basis recorded.
- **The preflight probe reservation composes unchanged.** Review-debt #14's reservation is TOKENS only (`PREFLIGHT_PROBE_RESERVE_TOKENS` via `governor.observeUsage`, never `observeResult` — the probe's cost is unmeasurable by construction), so the acp cell's new `--max-usd-per-case` does not interact with it: the probe reserves tokens against the token cap, observes no USD, and the per-case ceiling binds the cases exactly as on every other cell.
- **D10 unpause is NOT flipped here (decision).** The `schedule:` trigger stays absent and the matrix stays dispatch-only. D10's condition is "unpause only after W6.1 and W6.3 and W6.4 land"; the unpause is a deliberate act after these changes merge, not a side effect of them — flipping the trigger inside the same change would start real spend from an unreviewed commit. The plan re-enables the schedule in W6.4/W6.7; recorded here as the remaining W6.4 residue for that slice.
